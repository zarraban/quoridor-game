## 📌 1. Правила гри

Гра моделюється як антагоністичне змагання двох агентів на дискретному незваженому графі $9 \times 9$ (81 вершина, ребра між сусідніми клітинками).

| Параметр | Значення |
| :--- | :--- |
| **Поле** | $9 \times 9$ клітинок; координати `(рядок, стовпець)`, `(0,0)` — лівий верхній кут |
| **Старт** | Гравець 0 (синій) — `(8, 4)`, мета: рядок `0`. Гравець 1 (помаранчевий / бот) — `(0, 4)`, мета: рядок `8` |
| **Перемога** | Першим дійти пішаком до **будь-якої** клітинки протилежного краю |
| **Стінки** | По **10** на гравця; стінка займає 2 клітинки в довжину |
| **Хід** | Одна дія за такт: **крок пішака** *або* **встановлення стінки** |

### Кроки пішака

* Звичайний крок — на одну суміжну клітинку (вгору/вниз/вліво/вправо), якщо між клітинками немає стінки.
* **Стрибок** — якщо суміжна клітинка зайнята супротивником, а за ним (по прямій) немає стінки та краю поля, пішак перестрибує його.
* **Діагональний обхід** — якщо пряме перестрибування неможливе (стінка або край), пішак може стати на клітинку збоку від супротивника (за відсутності стінки між ними).

### Стінки

Стінка задається координатою `(r, c)` та орієнтацією (горизонтальна / вертикальна) і має індекс у межах $0 \dots 7$ по обох осях — вона лежить на перетині чотирьох клітинок `(r,c)`, `(r,c+1)`, `(r+1,c)`, `(r+1,c+1)`.

Стінку **не можна** поставити, якщо:

1. у гравця закінчилися стінки;
2. вона виходить за межі сітки;
3. на тому ж місці вже стоїть стінка тієї ж орієнтації;
4. вона **частково накладається** на сусідню стінку тієї ж орієнтації (`c±1` для горизонтальних, `r±1` для вертикальних);
5. вона **перехрещується** зі стінкою іншої орієнтації з тим самим якорем `(r, c)`;
6. 🔴 **No-block:** після її встановлення хоча б для одного з гравців не залишається жодного шляху до мети (перевіряється BFS).

## 🎮 2. Запуск і керування

```bash
pip install pygame
python main.py
```

**Меню:** режим (*PvP* / *vs Bot*) та формат серії (до **1 / 3 / 5** перемог), кнопка *Start*.
Після кожної партії клік мишею зараховує перемогу; коли хтось досягає цільової кількості перемог — повернення в меню.

| Дія | Керування |
| :--- | :--- |
| Крок пішака | ЛКМ по підсвіченій клітинці (режим *Move*) |
| Режим стінки ⇄ режим кроку | `Space` / `M` / `W` або кнопка в HUD |
| Повернути стінку (гор. ⇄ верт.) | `R` (у режимі стінки) |
| Поставити стінку | ЛКМ (якщо прев'ю синє — можна, червоне — не можна) |
| Скасувати режим стінки | ПКМ |
| Вихід у меню | `Esc` |

У режимі *vs Bot* людина грає за гравця 0, бот — за гравця 1.

## 🧱 4. Модель гри (GameState)

Стан повністю описується п'ятьма полями:

| Поле | Зміст |
| :--- | :--- |
| `pawns` | позиції двох пішаків `[(r, c), (r, c)]` |
| `walls_left` | кількість стінок, що лишилися у кожного |
| `h_walls`, `v_walls` | множини якорів горизонтальних / вертикальних стінок |
| `current_player` | чий хід (0 або 1) |
| `winner` | `None` або номер переможця |

Ключові методи:

* `is_wall_between(r1,c1,r2,c2)` — чи є стінка на ребрі між суміжними клітинками (перевіряє обидва можливі якорі стінки).
* `get_valid_moves(player)` — звичайні кроки, стрибки та діагональні обходи.
* `can_place_wall / place_wall` — перевірка правил 1–6 та застосування.
* `_path_exists(player)` — BFS-перевірка досяжності мети (для правила No-block).
* `shortest_path(player)` — BFS із відновленням маршруту; використовується і в оцінці, і в генерації стінок.
* `copy()` — швидке неглибоке копіювання стану для вузлів дерева пошуку.

## 🧠 5. Алгоритм ШІ: Minimax + α-β

Гра — з нульовою сумою та повною інформацією, тому бот обирає хід алгоритмом **Minimax** із фіксованою глибиною (за замовчуванням `depth = 2`: хід бота + відповідь людини).

* **MAX (бот)** — максимізує оцінку позиції.
* **MIN (людина)** — вважається раціональним суперником, що мінімізує оцінку.

```
                     [Поточний стан — MAX]
                    /                      \
        [Крок пішака]                  [Стінка]
         /        \                    /       \
   (MIN: найкращі     ...        (MIN: найкращі     ...
    дії людини)                   дії людини)
        ↓                              ↓
   Evaluator.evaluate()          Evaluator.evaluate()
```

### Псевдокод

```text
get_best_action(state, ai):
    best = None; best_score = -∞; α = -∞; β = +∞
    for action in candidate_actions(state, ai):
        child = state.copy(); apply(child, action)
        score = minimax(child, depth-1, α, β, maximizing=False)
        if score > best_score: best, best_score = action, score
        α = max(α, score)
    return best

minimax(state, depth, α, β, maximizing):
    if depth == 0 or state.winner is not None: return evaluate(state)
    for action in candidate_actions(state, current_player):
        child = state.copy(); apply(child, action)
        v = minimax(child, depth-1, α, β, not maximizing)
        MAX:  best = max(best, v); α = max(α, v)
        MIN:  best = min(best, v); β = min(β, v)
        if β <= α: break          # відсікання
    return best
```

### Генерація кандидатів (`get_candidate_actions`)

1. **Кроки пішака** — усі легальні, відсортовані за близькістю до цільового рядка (кращі ходи перевіряються першими → більше відсічень).
2. **Стінки** — не всі ~128 можливих, а лише відібрані (див. розділ 7).

## 📐 6. Евристична оціночна функція

Повний перебір неможливий (фактор розгалуження до ~130 дій), тому листові вузли оцінюються евристикою:

$$\text{Score} = w_{d}\cdot(\text{dist}_{\text{Human}} - \text{dist}_{\text{AI}}) + w_{w}\cdot(\text{walls}_{\text{AI}} - \text{walls}_{\text{Human}})$$

| Складова | Опис | Значення за замовчуванням |
| :--- | :--- | :--- |
| $\text{dist}$ | довжина найкоротшого шляху до мети, **BFS**, $O(V+E)$, з урахуванням усіх стінок | — |
| $w_d$ | вага різниці дистанцій (основний фактор) | **2.0** |
| $w_w$ | вага запасу стінок (мотивує економити стінки) | **0.4** |
| Термінальні стани | перемога бота / поразка | **±10000** |

Якщо шляху немає (теоретично неможливо через No-block), дистанція вважається рівною 100.

Витрата однієї стінки коштує $0.4$, а подовження шляху супротивника на 1 клітинку дає $+2.0$, тому бот ставить стінку, лише якщо вона реально затримує суперника хоча б на крок.

## ⚡ 7. Оптимізації та звуження дерева пошуку

1. **Альфа-бета відсікання.** Підтримуються межі $\alpha$ (найкраще для MAX) і $\beta$ (найкраще для MIN); гілка, що гарантовано гірша за вже знайдену альтернативу, відкидається. У кращому випадку складність падає з $O(b^{d})$ до $O(b^{d/2})$.
2. **Впорядкування ходів.** Кроки сортуються за близькістю до мети, стінки — за впливом (див. нижче), щоб сильні варіанти розглядались раніше й відсікання спрацьовувало частіше.
3. **Евристичний відбір стінок** (`_get_candidate_walls`):
   * **Кандидати:** стінки, що перекривають ребра на поточному найкоротшому шляху супротивника (обидві можливі позиції для кожного ребра), та стінки в околі $3\times3$ навколо його пішака (обох орієнтацій).
   * **Фільтр легальності:** `can_place_wall` (межі, накладання, перехрестя, No-block) — недопустимі стінки відсікаються ще до побудови вузлів.
   * **Оцінка впливу:** для кожної допустимої стінки перераховується BFS-довжина шляху супротивника; `impact = нова_дистанція − стара`.
   * **Top-K:** у дерево потрапляють лише **12** стінок із найбільшим `impact`.
4. **Лінійне копіювання стану.** `GameState.copy()` копіює лише списки та множини, без глибокого копіювання.

## 🔄 8. Інтеграція ШІ в ігровий цикл

* Після ходу людини в режимі *vs Bot* `Game._post_move()` запускає **окремий потік** `_bot_think_worker`, який викликає `MinimaxAgent.get_best_action(state, 1)`.
* Поки `bot_thinking = True`, введення гравця ігнорується, а інтерфейс не «зависає» — головний цикл (60 FPS) і далі малює кадри.
* Коли потік записує результат, `Game._update()` застосовує обраний хід до ігрового стану й повертає керування людині.
* Стан для пошуку береться як копія (`state.copy()` у кожному вузлі), тому розрахунок у потоці не змінює стан, який відображається.
